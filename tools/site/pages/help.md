# Getting help

AyMON is looked after by one person. Questions are welcome, and so is
patience: the order below is the fastest way to an answer.

## 1. Search this site

The search box at the top covers every guide and every example's README.
Most questions about *how* something works are answered in the example
that uses it — every example says what it teaches in its first lines.

## 2. Ask your own AI assistant, with the whole site attached

Every page of this site is also in **one text file**:

- [llms-full.txt](llms-full.txt) — every guide and example README, ready to paste
  or attach
- [llms.txt](llms.txt) — a short index of the same pages

Give `llms-full.txt` to Claude, ChatGPT or any assistant and ask your question
in your own language. It is usually the quickest way to find *which* example
shows what you need, or to explain an XML attribute you met in one.

!!! note
    An assistant can be wrong. If an answer does not work when you run it, the
    example's own files and its log are the truth — and that is a good
    question to bring to step 3.

## 3. Ask in Discussions

[**Discussions → Q&A**](https://github.com/akya-dev/AyMON/discussions/categories/q-a)
— English or Turkish (Türkçe sorular da olur). Say which example, which
platform, which engine build (`AyXDB -?` prints it) and paste the lines of the
project's `log\` that show the problem. **Remove passwords and connection
strings first.**

Questions are read about once a week. When a question shows that a page is
missing something, the page gets fixed — so the next person finds it in step 1.

## 4. Something is broken

An example that does not do what its README says, or an engine error, goes to
[**Issues**](https://github.com/akya-dev/AyMON/issues/new/choose).

A security problem does **not** go to Issues or Discussions — see
[Security](https://github.com/akya-dev/AyMON/security/policy).
